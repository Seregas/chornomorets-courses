# Design

## Context

Змінні оточення читаються один раз при старті процесу, а сервер працює під
LaunchAgent без watch. Через це будь-яка зміна — це правка `.env` на Mac mini
плюс `launchctl kickstart`. Для токена, який може протухнути, це означає тиху
відмову: приймання квитанцій перестає працювати, і ніхто про це не дізнається,
поки студент не поскаржиться.

## Goals / Non-Goals

**Goals**
- Змінювати те, що змінюється, з застосунку й без доступу до сервера.
- Не ламати вже розгорнутий сервер: поки налаштування не задане, працює оточення.
- Не віддавати секрети назад жодним запитом.

**Non-Goals**
- Переносити в налаштування все підряд. Таймаути, ліміти розміру файлу й
  інтервали кешу лишаються константами в коді: їх ніхто не крутитиме, а кожна
  зайва ручка — це ще одне значення, яке власник має розуміти й підтримувати.
- `GOOGLE_CLIENT_ID` лишається в оточенні: той самий ідентифікатор вшитий у
  збірку застосунку, тож змінити його лише на сервері неможливо.

## Decisions

### Критерій: що стає налаштуванням

- **Політика продукту** (кого вважати адміном, скільки днів показувати
  прострочену домашку) → налаштування курсу, редагує викладач.
- **Доступи, які протухають** (токен бота, чат) → налаштування курсу, секретні.
- **Особисте** (нагадування, адреса API) → лишається на пристрої людини.
- **Технічне підлаштування** (таймаути, ліміти, кеш) → константа в коді з
  коментарем, що пояснює число.

### Сховище: таблиця ключ-значення, а не колонки

Налаштувань мало й вони різнорідні. Окрема таблиця з іменованими колонками
вимагала б міграції на кожне нове значення; ключ-значення не вимагає. Типізацію
дає не база, а шар доступу: кожен ключ має відомий тип і значення за
замовчуванням в одному місці.

### Читання при кожному зверненні

Кеш у памʼяті процесу повернув би ту саму проблему, заради якої все робиться.
Звернень небагато, база локальна — SQLite читає рядок швидше, ніж мережа встигає
моргнути.

### Секрети

Зберігаються в тій самій базі, що й решта: вона лежить на тому ж диску, що й
`.env`, під тим самим обліковим записом — рівень довіри не змінюється. Але
назовні секрет не віддається ніколи: відповідь містить лише ознаку «задано».
Через це редагування односпрямоване — замінити можна, прочитати ні.

### Захист від втрати доступу

Список адмінів редагує адмін, тож теоретично можна зберегти список без себе й
замкнутися назовні. Сервер відмовляє, якщо в новому списку немає пошти того, хто
зберігає. Це єдиний спосіб, який не вимагає ні другого каналу, ні доступу до
сервера для відновлення.

## Risks / Trade-offs

- **Порожній список адмінів у базі** зробив би адмінкою доступною нікому.
  Тому порожнє значення трактується як «не задано» — працює оточення.
- **Дві точки правди** (оточення й база) ускладнюють діагностику. Пом'якшення:
  відповідь для адміна показує, звідки взяте кожне значення.

## Migration Plan

Нова таблиця створюється порожньою — поведінка не змінюється. Значення
переносяться з оточення в базу вручну, коли власник уперше відкриє екран
налаштувань. Змінні оточення лишаються на місці як запасний варіант.
