# Робота над цим проєктом

Застосунок для студентів онлайн-курсів Петра Чорноморця (психолог): бекенд на
Hono + Drizzle/SQLite та iOS-застосунок на SwiftUI. Монорепо. Працює наживо на
реальному курсі, збірки їздять у TestFlight.

`README.md` описує, **що це таке і як цим користуватися**. Цей файл — про те,
**як тут працювати**: інваріанти, яких не варто ламати, операційні дрібниці й
граблі, на які вже наступали.

## Мова

Код, коментарі, комміти, документація й спілкування — **українською**. Це не
косметика: продукт український, і власник читає й комміти, і коментарі в коді.

Коментарі пояснюють **чому**, а не що. «Тут ми фільтруємо масив» не потрібно;
«фільтруємо, бо Drive віддає 403 на файли, більші за 100 МБ, тим, хто не власник» —
потрібно. Особливо цінні коментарі про рішення, які виглядають дивно, поки не
знаєш причини: їх найлегше «полагодити» назад.

## Запуск

```bash
cd server && npm install && cp .env.example .env   # вписати ADMIN_EMAILS, GOOGLE_CLIENT_ID
npm run db:push && npm run seed && npm run dev      # http://localhost:3000
npm run typecheck                                  # обовʼязково перед коммітом

cd ios && xcodegen generate                        # ПОВТОРЮВАТИ після нових .swift
xcodebuild -project CoursesApp.xcodeproj -scheme CoursesApp \
  -destination 'platform=iOS Simulator,name=iPhone 17' build
```

Тестів немає — ні на сервері, ні в застосунку. Перевірка = `typecheck` + збірка +
запуск у симуляторі проти локального сервера. Якщо додаєте тести, це буде добре,
але не робіть це умовою для дрібної правки.

## Інваріанти

Порушення кожного з них зламає щось не одразу й не очевидно.

**1. Дані — тільки через `CourseRepository`.** `schema.ts` — єдине місце, що знає
про конкретні таблиці. Роути ходять через репозиторій. Це шов, щоб замінити
SQLite на Postgres, не чіпаючи ендпоінти.

**2. Відео — тільки через `video.ts`.** Бекенд віддає типізований дескриптор
(`direct | youtube | google-drive`), а не URL. Сирий `videoRef` клієнтові не
віддається ніде, крім цього шару. Застосунок має хендлер під кожен тип.

**3. Усе особисте висить на акаунті, не на пристрої.** Ключ `accounts.id` — це
`sub` із Google-токена: номер, який Google видає раз і назавжди. Пошта лежить
поруч і оновлюється при кожному вході (нею шарять відео й звіряють виписку), але
ключем бути не може — адресу змінюють.

`deviceId` лишився **рівно в одному місці** — `client_logs`: логи пишуться ще до
входу й саме тоді, коли ламається вхід. Не тягніть його більше нікуди.

Особисті ендпоінти не приймають ідентифікатор у запиті — сервер бере акаунт із
токена й відповідає `401` без входу. Клієнт показує на це запрошення увійти
(`LoadState.needsSignIn`), а не «не вдалося завантажити».

**4. Заочні акаунти.** Викладач знає пошту студента задовго до того, як той
поставить застосунок. `markPaymentByEmail` заводить акаунт `email:...`, а
`touchAccount` при першому справжньому вході переносить на нього всі рядки й
видаляє заглушку. Якщо додаєте нову таблицю з `accountId` — **допишіть її в
`claimPlaceholder`**, інакше її рядки загубляться при вході.

**5. Google-вхід просить лише пошту й ім'я.** Ніяких scope до Drive. Доступ до
записів роздає викладач пошарингом на Google-акаунт, і Drive сам вирішує, кого
пускати. Просити `drive.readonly` (читання всього диска людини) заради бейджа
«є доступ» — погана угода, до того ж це restricted scope: він вимагає щорічного
зовнішнього аудиту CASA перед публікацією. Не повертайте його.

Перевірено на пристрої: екран згоди просить лише пошту й ім'я. У Google Cloud
Console scope прописаний не був — SDK просив його прямо з застосунку, тож
чистити в консолі нічого. Проєкт стоїть у режимі Testing, де верифікація не
потрібна взагалі; вона знадобилася б лише при переході в production — і тепер,
без restricted scope, уже не знадобиться.

**6. Щоденник практик не покидає телефон.** `Services/PracticeJournal.swift` —
файл у Documents із `.completeFileProtection`. Це домашка на кшталт «занотуйте,
коли вас накриває»: такі записи бувають надто особистими, щоб їх бачив сервер чи
викладач. Не переносьте на бекенд «щоб синхронізувалося».

**7. Квитанції зберігає Телеграм.** Скріншот оплати пересилається в приватний
чат викладача (`telegram.ts`, `sendDocument`, а не `sendPhoto` — стиснення
псує цифри), у себе лишаємо тільки `file_id`. Свого сховища файлів немає й поки
не потрібно.

**8. Розпізнаний скріншот — не доказ оплати.** `ReceiptParsing` заповнює поля й
показує розбіжності, і на цьому все. Автоматично видавати доступ за картинкою
не можна — суму в скріншоті малює будь-хто за хвилину. Для справжньої
автоматизації потрібна банківська виписка.

## Модель даних

`Course` (вічний опис) → `Stream` (потік/cohort, може перевизначати опис
`*Override`-полями) → `Session` (заняття). Підписка — на **потік**, не на курс.

`Material` — поведінка визначається вмістом: є `description` → текст, є
`videoRef` → відео, є `url` → лінк, є `dueAt` → домашка з дедлайном. `typeId` —
косметичний ярлик із керованого каталогу, може бути порожнім. Власник
поліморфний: `course | stream | session` — запис і домашка належать конкретній
зустрічі, а дошка й реквізити — потоку.

`Payment` — на пару **«заняття + акаунт»**. Раніше стан оплати стояв на самому
занятті, одне значення на всіх; для курсу, де кожен платить за кожну зустріч
окремо, воно не здатне сказати правду нікому.

**Стан курсу визначає викладач** (`streams.status`), а не наявність занять
попереду. Порожній розклад означає лише, що наступну дату ще не назвали. На
цьому вже помилялися: курс, що триває, показувався «завершеним».

## iOS

`project.yml` — **джерело правди**, `.xcodeproj` похідний. Після додавання
файлів обовʼязково `xcodegen generate`, інакше файл не потрапить у збірку.

`.xcodeproj/project.pbxproj` закоммічений, тож після кожного `xcodegen generate`
він показується зміненим. Якщо в коміті немає змін у `project.yml` — відкидайте
цей шум: `git checkout -- ios/CoursesApp.xcodeproj/project.pbxproj`.

Архітектура: SwiftUI + `@Observable`, MVVM. DI — через `AppEnvironment`
(`.injecting(env, auth:)`), у прев'ю підставляється `PreviewRepository`. Кожен
екран — `LoadState` + `LoadStateView`.

**Пастка з навігацією.** `HomeView` і `CatalogView` мають типізований шлях
`[Route]`. `NavigationLink(value:)` зі значенням **іншого** типу в такому стеку
SwiftUI мовчки ігнорує — тап не робить нічого, помилки немає. Так одного разу
перестали відкриватися заняття. Якщо треба відкрити екран із будь-якого стека —
`@State` + `.navigationDestination(item:)`. І не обгортайте рядок у `Button`,
якщо в ньому є вкладені кнопки: вони перестануть ловити тапи. `.contentShape` +
`.onTapGesture`.

**Дати показують рік завжди** (`Fmt.dayTime` → «23 лют. 2026, 18:00»). Курси
повторюються потоками рік за роком, і викладач гортає однаково минулі й
майбутні; «23 лют.» без року читається неоднозначно.

**Токен живе годину.** Google ID-token протухає, і `APIClient` на `401` один раз
мовчки оновлює його через `TokenRefresher` і повторює запит. Хук ставиться на
старті застосунку. Без цього людина раз на годину бачила б порожній розклад.

**Офлайн.** Успішні GET кешуються на диск; без мережі віддається копія й
показується банер «дані від …». Помилки сервера з кешу не рятуються, і відповіді,
що залежать від того, хто питає (`me`, оплати), кешуються з `cached: false` —
інакше «ви не адмін» пережило б вхід.

## Дані живої бази

`seed.ts` спершу **витирає** базу — на живій його запускати не можна. Для змін —
ідемпотентні скрипти в `server/src/scripts/`:

```bash
npx tsx src/scripts/add-biohardcore.ts                    # додати курс, не чіпаючи решту
npx tsx src/scripts/add-motivation-base.ts
npx tsx src/scripts/add-laziness.ts
npx tsx src/scripts/mark-paid.ts <email> <stream-id>      # відмітити оплати по пошті
```

Перед будь-якою зміною схеми — бекап: `sqlite3 data.db ".backup копія.db"`.

`npm run db:push` **інтерактивний**: на перейменуваннях він питає «rename or
drop?», і в неінтерактивному запуску обривається, лишивши базу зламаною
(API почне віддавати 500). Для міграцій із перейменуваннями пишіть SQL руками
й застосовуйте через `sqlite3`.

## Деплой

Сервер живе на Mac mini власника під двома LaunchAgents (`~/Library/LaunchAgents/`):

- `com.chornomorets.courses-api` — сам API. Шлях до `node` **абсолютний** і `PATH`
  задано явно: launchd не успадковує середовище користувача, і без цього агент
  падає з `env: node: No such file` (код 127).
- `com.chornomorets.courses-tunnel` — `cloudflared`, який публікує API на
  `https://courses-api.sirohas.space`.

```bash
launchctl kickstart -k gui/$(id -u)/com.chornomorets.courses-api   # перезапуск після змін
tail -f server/logs/api.error.log
```

Агент запускає код **без watch**, тож зміни на сервері підхоплюються лише
перезапуском.

## TestFlight

```bash
cd ios && source ~/.zshenv
TEAM_ID=GW39JC2R67 API_BASE_URL=https://courses-api.sirohas.space \
ASC_USERNAME="$APPLE_ID" ASC_PASSWORD="$APPCONNECT_GENOMICS_DEPLOY_PW" \
./scripts/testflight.sh
```

Перед кожним вивантаженням **підняти `CURRENT_PROJECT_VERSION`** у `project.yml`:
Apple відхиляє збірку з номером, який уже був.

Пароль застосунку привʼязаний до Apple ID, а не до застосунку, тому той, що вже
лежить у `~/.zshenv` від іншого проєкту, підходить і тут. App Store Connect
API-ключ потребує ролі Admin, якої немає, тож використовується шлях через Apple ID.

`API_BASE_URL` вшивається в збірку. **Без публічного бекенда тестова збірка
марна** — на чужому телефоні будуть порожні екрани й банер «немає звʼязку».

## Комміти

Коммітити й пушити на кожній віхі, але **не рідше разу на день роботи** — це
прямий запит власника.

Повідомлення пояснює **навіщо**, а не перелічує файли. Перший рядок — суть
українською, далі абзаци про причину й наслідки. Взірець тону — `git log`.

**Не використовуйте зворотні лапки в `-m`**: zsh виконає вміст як команду й
зʼїсть слово з повідомлення. Пишіть через `git commit -F -` і heredoc.

Трейлери в кінці:

```
Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
Claude-Session: <посилання на сесію>
```

## Граблі, на які вже наступали

Кожен пункт колись зʼїв годину — не повторюйте.

- **Drive не віддає байти відео.** `403 cannotDownloadFile`: власник вимкнув
  завантаження для глядачів, і це свідома політика — файли платного курсу не
  мають розходитися. Тому Drive-відео відкривається плеєром самого Drive у
  `SFSafariViewController` (він ділить сесію з Safari, тож людина вже залогінена).
  Не намагайтеся тягнути вміст через API «правильніше» — там тупик.
- **AVKit мовчить.** Коли він не розуміє формат, він малює перекреслений плей і
  не каже нічого. `status == .failed` не спрацьовує; треба слухати ще
  `failedToPlayToEndTime` і `newErrorLogEntry`. Причину знайшли лише коли
  застосунок почав надсилати діагностику на сервер (`RemoteLog` → `POST /logs`,
  `GET /admin/logs`). Це найкоротший шлях до правди про поведінку на пристрої —
  користуйтеся ним замість здогадок.
- **`TARGETED_DEVICE_FAMILY` треба задавати в кожному таргеті.** XcodeGen
  перекриває значення з project-рівня власним `"1,2"`, застосунок починає
  претендувати на iPad, і Apple відхиляє вивантаження помилкою 90474
  (вимагає всі чотири орієнтації для iPad-мультитаскінгу). Тому в обох таргетах
  стоїть `"1"` — лише iPhone.
- **Тривалість HLS буває NaN**, і збереження позиції перегляду через це тихо не
  працювало. `duration` — опціональна.
- **`Fmt.date` спотикався на дробових секундах** (`…T20:51:35.601Z`) — потрібні
  два ISO-формати, з фракціями й без.
- **`SIMCTL_CHILD_` — обовʼязковий префікс** для env-змінних при
  `xcrun simctl launch`, інакше вони просто не доходять.
- **Демо-env для скриншотів:** `START_TAB`, `SKIP_NOTIF_PROMPT`, `OPEN_COURSE`,
  `OPEN_STREAM`, `OPEN_SESSION`, `OPEN_MATERIAL`, `OPEN_QUESTIONS`, `OPEN_PULSE`,
  `OPEN_JOURNAL`.

## Домовленості з власником

- Він адмін (`ADMIN_EMAILS` = його Google-акаунт), адмінка інлайн у застосунку.
- Він просить **брати в роботу все, що не заблоковане**, і приносити йому лише
  те, що справді вимагає його рішення.
- Він тестує на своєму телефоні через TestFlight, тож збірку варто вивантажувати
  одразу після помітної зміни, а не збирати їх пачками.
- Чекають на нього: токен телеграм-бота з `chat_id` (сповіщення про заявки й
  квитанції) і дата наступного заняття «Біохардкору».
